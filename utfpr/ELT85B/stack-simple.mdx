## ESP32 + PlatformIO (VS Code) + Wokwi (simulador) + Node-RED + SQLite

Sim — essa versão é **mais simples e excelente para um projeto didático introdutório de IoT**. O Grafana/InfluxDB pode ficar como uma etapa avançada posterior.

## Arquitetura proposta

```text
                    DESENVOLVIMENTO
        ┌──────────────────────────────┐
        │       VS Code + PlatformIO   │
        │                              │
        │          ESP32 / C++         │
        └──────────────┬───────────────┘
                       │
                       ▼
              ┌─────────────────┐
              │      Wokwi      │
              │   Simulador     │
              │                 │
              │ ESP32 + Sensors │
              └────────┬────────┘
                       │
                       │ MQTT
                       ▼
              ┌─────────────────┐
              │    Mosquitto    │
              │   MQTT Broker   │
              └────────┬────────┘
                       │
                       ▼
              ┌─────────────────┐
              │    Node-RED     │
              │                 │
              │ MQTT            │
              │ Processing      │
              │ Rules           │
              │ SQLite          │
```

### Stack

| Componente             | Responsabilidade                            |
| ---------------------- | ------------------------------------------- |
| **VS Code**            | Ambiente de desenvolvimento                 |
| **PlatformIO**         | Build, bibliotecas e gerenciamento do ESP32 |
| **Wokwi**              | Simulação do hardware                       |
| **Mosquitto**          | Broker MQTT                                 |
| **Node-RED**           | Integração e processamento                  |
| **Node-RED Dashboard** | Visualização e controle                     |
| **SQLite**             | Persistência dos dados                      |

## Exemplo de aplicação

Eu sugiro usar uma **Estação IoT de Monitoramento Ambiental**.

O ESP32 simulado terá:

```text
┌─────────────────────────────┐
│            ESP32            │
│                             │
│  DHT22 ───► Temperatura     │
│        └──► Umidade         │
│                             │
│  LDR ─────► Luminosidade    │
│                             │
│  Button ──► Entrada digital │
│                             │
│  LED ─────► Atuador         │
│                             │
└─────────────────────────────┘
```

Mensagem MQTT:

```json
{
  "device": "esp32-01",
  "temperature": 27.4,
  "humidity": 68.2,
  "light": 742
}
```

Tópico:

```text
iot/esp32-01/telemetry
```

## Node-RED

O fluxo principal:

```text
[MQTT IN]
    │
    ▼
[JSON]
    │
    ▼
[Function]
    │
    ├───────────────► [Dashboard]
    │
    ▼
[SQLite]
```

E podemos acrescentar regras:

```text
                    ┌── temperatura > 30 ──► 🔴 ALERTA
                    │
MQTT → JSON → Rule ─┼── temperatura ≤ 30 ──► 🟢 NORMAL
                    │
                    └──────────────────────► SQLite
```

Para esse projeto didático, eu recomendo usar o **ESP32 DevKit V1 baseado no ESP32-WROOM-32**.

### Minha recomendação

**ESP32 DevKit V1 / ESP32-WROOM-32**

É uma ótima escolha para:

- PlatformIO + VS Code
- Wokwi
- MQTT
- Node-RED
- DHT22
- LDR
- LEDs
- botões
- OLED I²C
- sensores analógicos
- relés
- Wi-Fi
- Bluetooth/BLE

No `platformio.ini`:

```ini
[env:esp32dev]
platform = espressif32
board = esp32dev
framework = arduino

monitor_speed = 115200
```

Esse `board = esp32dev` é particularmente conveniente porque o PlatformIO já possui suporte para placas ESP32 DevKit genéricas.

### No Wokwi

Para o `diagram.json`, você pode utilizar:

```json
{
  "version": 1,
  "author": "IoT Lab",
  "editor": "wokwi",
  "parts": [
    {
      "type": "board-esp32-devkit-v1",
      "id": "esp",
      "top": 0,
      "left": 0,
      "attrs": {}
    }
  ]
}
```

Assim temos praticamente o mesmo alvo:

```text
              ┌──────────────────┐
              │      Wokwi       │
              │                  │
              │ ESP32 DevKit V1  │
              │   WROOM-32       │
              └────────┬─────────┘
                       │
                       │ Wi-Fi
                       ▼
                    MQTT
                       │
                       ▼
                  Mosquitto
                       │
                       ▼
                   Node-RED
                       │
             ┌─────────┴─────────┐
             ▼                   ▼
          SQLite             Dashboard
```

### Por que não escolher ESP32-C3/C6?

Para **esse primeiro laboratório**, eu evitaria começar com C3, C6 ou S3.

| Modelo                         | Para este projeto          |
| ------------------------------ | -------------------------- |
| **ESP32-WROOM-32 / DevKit V1** | ⭐⭐⭐⭐⭐ **Recomendado** |
| ESP32-S3                       | ⭐⭐⭐⭐                   |
| ESP32-C3                       | ⭐⭐⭐⭐                   |
| ESP32-C6                       | ⭐⭐⭐                     |
| ESP32-H2                       | ⭐⭐                       |

O **ESP32-WROOM-32** tem uma enorme quantidade de exemplos, bibliotecas e projetos educacionais, além de ser muito bem suportado pelo Wokwi e PlatformIO.

### Hardware didático sugerido

Eu montaria o primeiro kit assim:

```text
ESP32 DevKit V1
│
├── DHT22       → temperatura/umidade
├── LDR         → luminosidade
├── LED         → atuador
├── Push Button → entrada
├── OLED SSD1306 → display local
└── Buzzer      → alerta
```

E a evolução seria:

```text
             ┌──────────────┐
             │ ESP32-WROOM-32│
             └───────┬──────┘
                     │
          ┌──────────┼──────────┐
          ▼          ▼          ▼
       Sensores    Atuadores   OLED
          │          │
          └─────┬────┘
                ▼
              Wi-Fi
                │
                ▼
              MQTT
                │
                ▼
            Node-RED
           ┌────┴────┐
           ▼         ▼
        SQLite    Dashboard
```

**Portanto, para o projeto que estamos montando, eu padronizaria tudo em `ESP32 DevKit V1 (ESP32-WROOM-32)`**, tanto no hardware físico quanto no Wokwi e no PlatformIO. Isso reduz bastante a complexidade para os alunos e deixa o foco nos conceitos de IoT, MQTT, Node-RED e banco de dados.

## Stack tecnológica definitiva

Eu padronizaria o laboratório em:

```text
┌─────────────────────────────────────────────┐
│              DESENVOLVIMENTO                │
│                                             │
│          VS Code + PlatformIO               │
└───────────────────┬─────────────────────────┘
                    │
                    ▼
┌─────────────────────────────────────────────┐
│                 HARDWARE                    │
│                                             │
│       ESP32 DevKit V1 / WROOM-32            │
│                 +                           │
│              Wokwi                         │
└───────────────────┬─────────────────────────┘
                    │
                  Wi-Fi
                    │
                  MQTT
                    │
                    ▼
┌─────────────────────────────────────────────┐
│                INTEGRAÇÃO                   │
│                                             │
│               Mosquitto                    │
│                   ↓                         │
│               Node-RED                     │
└───────────────┬─────────────┬───────────────┘
                │             │
                ▼             ▼
           ┌─────────┐   ┌──────────────┐
           │ SQLite  │   │  Dashboard   │
           │         │   │  Node-RED    │
           └─────────┘   └──────────────┘
```

Isso mantém a primeira versão **tecnicamente acessível aos alunos**, mas já introduz praticamente todos os conceitos fundamentais de uma arquitetura IoT real. Depois, uma segunda etapa pode substituir o SQLite por **InfluxDB + Grafana** para introduzir bancos de séries temporais e observabilidade.
