Laboratório 13

Checklist — automação de processos com n8n: eventos, aprovações e agentes​

  • n8n do grupo na rede do LAB IoT, credenciais importadas, notificação pelo ntfy e workflows exportados para o Git (T1)
  • Node-RED publica eventos de alarme; o n8n abre a ocorrência, avisa e escala se ninguém reconhecer (T2)
  • Relatório do turno agendado: API do Node-RED, ocorrências do n8n, arquivo no repositório e aviso (T3)
  • Mudança de setpoint por formulário, com aprovação humana, comando MQTT e conferência do resultado (T4)
  • n8n como servidor MCP: o agente consulta a câmara e só pede mudanças, testado sem IA e com o agente (T5)
  • Workflow de erros, lint dos workflows no CI e ensaio de recuperação a partir do Git (T6)
  • Previsões P1–P4 respondidas no README.md
  • Nenhum token no repositório nem no chat; nenhum push --force; cada tarefa num commit Tn:
  • Logout do Git, do gh e da conta do n8n no computador do laboratório
Pontuação

T1…T6 = 100 pts (esta aula não tem desafios): T1 10 · T2 20 · T3 15 · T4 20 · T5 15 · T6 20. O autograder normaliza para 0–10. Vale o commit Tn: mais recente de cada tarefa.

WinLibs (GCC + MinGW-w64): Compilador C/C++ nativo para Windows, usado pelo PlatformIO no ambiente native.

  • O pio test -e native compila os testes com o gcc/g++ do computador, e o PlatformIO não instala esse compilador. Sem ele, aparece o erro 'gcc' não é reconhecido como um comando interno.
  • WinLibs: baixe a versão mais recente (x86_64, POSIX, UCRT) via GitHub. É portátil e não precisa de administrador.
powershell -NoProfile -Command "$a = (Invoke-RestMethod https://api.github.com/repos/brechtsanders/winlibs_mingw/releases/latest).assets | Where-Object { $_.name -like 'winlibs-x86_64-posix-seh-gcc-*-mingw-w64ucrt-*.zip' -and $_.name -notlike '*llvm*' } | Select-Object -First 1; curl.exe -L -o (Join-Path $env:TEMP 'winlibs.zip') $a.browser_download_url"
  • Descompacte em %USERPROFILE%\mingw64 e apague o .zip:
tar -xf "%TEMP%\winlibs.zip" -C "%USERPROFILE%" && del "%TEMP%\winlibs.zip"
  • Acrescente %USERPROFILE%\mingw64\bin ao PATH do usuário (rode uma vez só):
powershell -NoProfile -Command "[Environment]::SetEnvironmentVariable('Path', [Environment]::GetEnvironmentVariable('Path','User') + ';' + $env:USERPROFILE + '\mingw64\bin', 'User')"
  • Feche e abra o VS Code de novo para ele ler o novo PATH. Depois confira:
gcc --version

O Node-RED dos Labs 05 a 10 é ótimo com fluxos de dados: uma leitura a cada 2 s, uma escala, um gráfico. Uma fábrica também tem processos: um alarme que alguém precisa reconhecer, uma mudança de setpoint que um supervisor precisa aprovar, um relatório que sai a cada troca de turno. Processos esperam por pessoas, duram minutos ou horas e precisam deixar registro.

O n8n é uma plataforma de automação de processos (workflow automation): cada processo é um workflow de nós, disparado por um gatilho (uma mensagem MQTT, um horário, um formulário, uma chamada MCP). O n8n guarda cada execução, sabe esperar por uma pessoa sem travar nada e fala com centenas de serviços.

Nesta aula, cada ferramenta fica com o que faz melhor:

No Node-RED (borda)No n8n (processo)
recebe toda a telemetria e grava no SQLiterecebe só eventos (o alarme mudou)
http in responde /api/estado e /api/turnoconsulta essas APIs quando um processo precisa
fluxo sempre rodando, sem histórico de execuçõescada execução registrada: quem, quando, com que dados
—espera uma pessoa (reconhecer, aprovar) por minutos ou dias

Objetivos​

  • Subir e operar o n8n na rede do LAB IoT, com credenciais fora do repositório.
  • Separar dados (Node-RED) de eventos e processos (n8n), e medir por quê.
  • Montar processos com espera por pessoas: reconhecimento com escalonamento e aprovação.
  • Integrar por API: HTTP ao Node-RED, MQTT para a câmara, ntfy para o celular.
  • Expor processos a um agente de IA por MCP sem dar a ele o poder de escrever na planta.
  • Tratar workflows como código: exportação, lint no CI, workflow de erros e recuperação.

Material​

  • O LAB IoT do lab13-x (gerado pelo gen_iot_aluno.py, pode ser com --sem-fuxa): mosquitto e Node-RED com node-red-node-sqlite.
  • O repositório do grupo, que nasce do lab13-template: camara-sim/, o fluxo do Node-RED, o docker-compose.yml do n8n, dois workflows prontos e os scripts de teste.
  • ntfy: o app no celular ou o navegador, com o servidor e o token do grupo (linha do ntfy no credenciais.txt do LAB IoT) ou o ntfy.sh público, com um tópico difícil de adivinhar.
  • Python 3 com o pacote mcp (T5) e o VS Code com o Copilot do Lab 12 (T5).
n8n: o que esta aula usa

O n8n roda num contêiner do grupo, na versão stable mais recente. O código é aberto sob a Sustainable Use License: usar uma instância própria para aprender e para processos internos é permitido; oferecer o n8n como serviço para terceiros, não. A aula não usa a nuvem do n8n, os nós de IA com chave de API nem os recursos pagos (variáveis, ambientes, Git integrado).
