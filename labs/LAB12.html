Checklist — IA no desenvolvimento: agentes, MCP e revisão​

  • Agente do VS Code funcionando e AGENTS.md com o contexto do projeto, comparado com e sem ele (T1)
  • Rampa de setpoint feita com o agente a partir de testes escritos antes, sem mexer nos testes (T2)
  • Wokwi MCP: o agente simula o firmware, comprova a rampa e escreve um cenário que passa no wokwi-cli (T3)
  • Servidor MCP da câmara com os limites no servidor, testado sem IA e usado pelo agente (T4)
  • Injeção de prompt testada e mitigada: limite, menor privilégio, aviso e auditoria (T5)
  • Contribuição revisada por pessoas, pela IA e pelos testes; defeitos corrigidos, testados e juntados por PR com CI verde (T6)
  • IA-LOG.md preenchido em todas as tarefas
  • Previsões P1–P4 respondidas no README.md
  • Nenhum token no repositório nem no chat; nenhum push --force; cada tarefa num commit Tn:
  • Logout do Git, do gh e da conta GitHub do VS Code no computador do laboratório
Pontuação

T1…T6 = 100 pts (esta aula não tem desafios): T1 10 · T2 20 · T3 15 · T4 20 · T5 15 · T6 20. O autograder normaliza para 0–10. Vale o commit Tn: mais recente de cada tarefa.

Um agente de IA escreve, num minuto, o código que levaria uma tarde. Ele também inventa uma API que não existe mais, apaga um teste que atrapalha e obedece a uma frase escondida num arquivo. Nesta aula, a IA entra no fluxo de trabalho da disciplina, com os mesmos controles que você já usa para código humano: testes, CI, revisão e limites no equipamento.

O fio condutor é o MCP (Model Context Protocol): o padrão aberto com que um agente usa ferramentas fora do chat. Um servidor MCP é um programa que roda no seu computador e diz ao agente "eu sei fazer isto, com estes parâmetros". O agente pede; o VS Code roda; você aprova.

O modelo não executa nada. Ele só pede uma ferramenta; quem a executa é o VS Code, no seu computador. Por isso as proteções que valem de verdade ficam no servidor, e não no prompt.

Política de IA nesta aula
  • Pode usar IA em todas as tarefas. É o assunto da aula.
  • Cada uso que mudou algo vai para o IA-LOG.md: ferramenta, pedido, o que aceitou, o que corrigiu e como verificou. A clareza do registro vale nota; a quantidade de IA, não.
  • Você responde por tudo o que entra num commit seu, escrito por você ou pela IA.
  • Nunca cole token, senha ou o .env no chat. O que vai para o chat vai para a nuvem.

Objetivos​

  • Dar contexto a um agente (AGENTS.md) e medir a diferença.
  • Usar testes escritos antes como contrato e juiz do código gerado.
  • Conectar o agente a ferramentas por MCP: o servidor do Wokwi e um servidor seu.
  • Escrever um servidor MCP com o SDK oficial, com limites, anotações e testes sem IA.
  • Reconhecer e mitigar injeção de prompt com menor privilégio, validação e auditoria.
  • Comparar a revisão de código humana, por IA e por testes.

Parte 2 — Agente guiado por testes​

2.1 O contrato​

Acrescente ao lib/camara_logica/camara_logica.h, dentro do namespace camara:

// Aproxima spAtual de spAlvo sem passar de 'taxaCporMin' °C por minuto, em dtS segundos.
//  - taxaCporMin <= 0 desliga a rampa: devolve spAlvo direto;
//  - dtS <= 0 (relógio parado ou voltando): devolve spAtual;
//  - spAlvo NaN: devolve spAtual (alvo inválido não move a câmara);
//  - spAtual NaN (primeira chamada): devolve spAlvo;
//  - nunca passa do alvo.
float rampaSetpoint(float spAtual, float spAlvo, float taxaCporMin, float dtS);

4.2 O que falta no servidor​

PeçaRequisito
definir_setpoint(celsius)aceita de 20 a 45 °C (política do laboratório, menor que os 55 °C da câmara); fora disso, ToolError e nada muda; escreve Camara.setpoint como Double

Pode (e deve) usar o agente para escrever. Leia o resultado com atenção:

A IA conhece a versão antiga do SDK

Quase todo exemplo na internet, e na memória dos modelos, usa from mcp.server.fastmcp import FastMCP, do SDK 1.x. No 2.x, isso falha com uma mensagem que já diz o que fazer:

ModuleNotFoundError: No module named 'mcp.server.fastmcp'. This is mcp 2.x, where FastMCP was
renamed to MCPServer (from mcp.server.mcpserver import MCPServer) and other APIs changed

O esqueleto já usa o MCPServer. Para erros esperados (um setpoint fora da faixa), use ToolError (from mcp.server.mcpserver.exceptions import ToolError): o agente recebe uma mensagem clara, e não um traceback.

Parte 5 — Injeção de prompt e menor privilégio​

Para o modelo, tudo o que chega é texto: o seu pedido, o AGENTS.md e o resultado das ferramentas. Se um resultado contém uma frase com cara de instrução, o modelo pode obedecer. É a injeção de prompt indireta, e o livro de ocorrências do turno, escrito por qualquer operador, é a porta de entrada.

5.2 As mitigações​

Nenhuma sozinha basta. Implemente as quatro no camara_mcp.py:

  1. Limite no servidor (já da T4): 55 °C é recusado, qualquer que seja o pedido.
  2. Menor privilégio: a opção --somente-leitura cria o servidor sem as ferramentas de escrita. Registre-o como um segundo servidor no mcp.json, camara-leitura, com "args": [".../camara_mcp.py", "--somente-leitura"]. Relatórios usam só ele: no ícone de ferramentas do chat, desmarque o servidor camara.
  3. Aviso de conteúdo não confiável: ler_ocorrencias devolve um objeto com um campo aviso, que diz que o texto é registro de pessoas e não instrução, e as entradas.
  4. Auditoria: toda chamada de escrita, aceita ou recusada, vira uma linha em mcp-camara/auditoria.log (data, ferramenta, argumentos, resultado).

Repita as duas rodadas com as mitigações e complete a tabela. Depois:

Ao terminar — máquina de laboratório

Antes de sair, faça logout para não deixar sua conta do GitHub ativa na máquina (limpa a credencial salva do git e encerra a sessão do gh).
