## Projeto: Laboratório IoT com ESP32

**Stack:** ESP32 + PlatformIO + VS Code + Wokwi + MQTT + Node-RED + SQLite + Grafana

### Objetivo geral

Desenvolver uma aplicação IoT completa capaz de **coletar dados de sensores, transmitir os dados por MQTT, processá-los com Node-RED, armazená-los em SQLite e apresentar informações em dashboards Grafana**, utilizando o Wokwi como ambiente de simulação do ESP32.

## 04 — MQTT

Aqui entra um conceito fundamental de IoT:

```text
Publisher             Broker             Subscriber

ESP32 ───────────────► MQTT ◄──────────── Node-RED
```

Sugestão de tópicos:

```text
iot/esp32-01/temperature
iot/esp32-01/humidity
iot/esp32-01/status
```

Ou, melhor ainda, uma mensagem única:

```text
iot/esp32-01/telemetry
```

Payload:

```json
{
  "device": "esp32-01",
  "temperature": 27.4,
  "humidity": 68.2
}
```

Isso permite ensinar:

- Publisher
- Subscriber
- Broker
- Topic
- Payload
- QoS
- Retained messages
- Last Will
- Telemetria

# 05 — Node-RED

O Node-RED passa a funcionar como o **middleware IoT**.

Fluxo inicial:

```text
             MQTT
               │
               ▼
        ┌─────────────┐
        │ MQTT IN     │
        └──────┬──────┘
               ▼
        ┌─────────────┐
        │ JSON        │
        └──────┬──────┘
               ▼
        ┌─────────────┐
        │ Function    │
        └──────┬──────┘
               │
       ┌───────┴────────┐
       ▼                ▼
    SQLite           Dashboard
```

Exemplo de processamento:

```javascript
const temperature = msg.payload.temperature;

if (temperature > 30) {
  msg.alert = true;
  msg.alertMessage = "Temperatura elevada";
}

return msg;
```

Assim o aluno começa a perceber que Node-RED não é apenas um visualizador: ele pode atuar como **camada de integração e processamento**.

# 06 — SQLite

Banco inicial:

```sql
CREATE TABLE telemetry (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    device TEXT NOT NULL,
    temperature REAL,
    humidity REAL,
    timestamp DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

Cada mensagem MQTT pode gerar:

```text
ESP32
  ↓
MQTT
  ↓
Node-RED
  ↓
INSERT
  ↓
SQLite
```

Exemplo:

```sql
INSERT INTO telemetry
(device, temperature, humidity)
VALUES
('esp32-01', 27.4, 68.2);
```

Consultas didáticas:

```sql
SELECT *
FROM telemetry
ORDER BY timestamp DESC;
```

Temperatura média:

```sql
SELECT AVG(temperature)
FROM telemetry;
```

Máxima:

```sql
SELECT MAX(temperature)
FROM telemetry;
```

Yes. For your **didactic IoT project**, these time-series databases are useful alternatives to SQLite. I would actually position them as a second stage of the architecture.

### Time-series databases

| Database       | Best suited for      | IoT role                      | Complexity |
| -------------- | -------------------- | ----------------------------- | ---------- |
| **Prometheus** | Metrics + monitoring | Infrastructure/device metrics | ⭐⭐       |
| **Graphite**   | Metrics over time    | Monitoring                    | ⭐⭐       |
| **InfluxDB**   | IoT telemetry        | Sensor data / time series     | ⭐⭐⭐     |
| **OpenTSDB**   | Large-scale metrics  | Distributed time-series data  | ⭐⭐⭐⭐   |

### Recommended architecture

For the laboratory we have been building, I would use **SQLite first**, then introduce **InfluxDB** as the dedicated time-series database:

### Why InfluxDB is particularly interesting here

For IoT, the data naturally looks like:

```text
timestamp + device + measurement + value
```

For example:

```text
2026-08-08 14:50:00
device=esp32-01
temperature=27.4
humidity=68.2
```

This is exactly the type of workload for which a time-series database is designed.

You can therefore teach the students the evolution:

```text
Level 1
ESP32 → MQTT → Node-RED → SQLite → Grafana

Level 2
ESP32 → MQTT → Node-RED → InfluxDB → Grafana

Level 3
ESP32 → MQTT → Node-RED → InfluxDB
                         ↓
                    Processing
                         ↓
                       n8n
                         ↓
                     Alerts/API
```

For your specific **ESP32 + Wokwi + Node-RED + Grafana** laboratory, my recommendation is:

> **SQLite for teaching relational persistence + InfluxDB for teaching real IoT time-series storage + Grafana for visualization.**

That gives students a very useful comparison between a **general-purpose relational database** and a **purpose-built time-series database**.
